MÓDULO 1 — TREINAMENTO

1.1 Perfil do Client Partner

Página de referência em formato de guia consultável. Exibir as seguintes seções como cards expansíveis (accordion):

Definição do Papel:

O Client Partner é o profissional responsável pela gestão estratégica de relacionamentos com clientes-chave da Kienbaum. Não é vendedor tradicional — é um consultor de confiança que conecta necessidades do cliente ao portfólio de soluções da Kienbaum.

Portfólio de Produtos que o CP precisa dominar:

Assessment / Competence Check → alimenta Coaching, PDI Sprint, Análise de Sucessores e Peers Leadership

Coaching Executivo (alimentado pelo Assessment): desenvolvimento individual profundo, transformação comportamental e estratégica

Estratégia de Sucessão (BBB): mapeamento de potenciais, matriz de sucessão para posições críticas

PDI Sprint: para lideranças iniciantes, acompanhamento de implementação, duração de 6 meses

Executive Search / Peers Leadership

Outros: Redesenho Organizacional, Governança Empresarial, Governança Familiar, Jornadas Customizadas

Tipos de Atuação e Remuneração associada:

Geração + Gestão do Projeto: identifica, gera demanda, estrutura proposta, negocia, fecha, gerencia projeto do início ao fim, conduze encerramento e NPS → 10% sobre faturamento bruto

Geração + Acompanhamento: identifica, gera demanda, estrutura, fecha, handoff completo para entrega, follow-ups estratégicos, ponto de escalada, não participa do dia a dia → 5% sobre faturamento bruto

Por Atividade: execução de atividade técnica específica (remuneração conforme tabela do produto)

Competências essenciais do CP:

Visão estratégica de negócios

Capacidade consultiva de diagnóstico

Gestão de relacionamentos de longo prazo (C-level)

Domínio do portfólio Kienbaum

Negociação em ambiente boutique (não transacional)

Inteligência emocional e presença executiva

1.2 Técnicas de Negociação

Página com abas: GPCT | BANT | SPIN Selling | Matriz Go/No-Go

Aba GPCT (Framework Consultivo — Recomendado Kienbaum):

Formulário interativo de qualificação com score automático (0 a 8 pontos):

Dimensão Pergunta-chave Score (0-2) G — Goals (Metas) Quais são as metas estratégicas da empresa nos próximos 12-24 meses? 0 / 1 / 2 P — Plans (Planos) Quais iniciativas já estão planejadas para atingir essas metas? 0 / 1 / 2 C — Challenges (Desafios) Quais obstáculos estão impedindo o alcance das metas? 0 / 1 / 2 T — Timeline Há urgência? Qual o prazo para resolver o desafio? 0 / 1 / 2

Score 0 = Não identificado / Score 1 = Parcialmente identificado / Score 2 = Claramente identificado

Aba BANT (Qualificação Comercial — Complementar):

Dimensão Pergunta-chave Score (0-2) B — Budget Há orçamento disponível ou aprovável para este projeto? 0 / 1 / 2 A — Authority O interlocutor tem poder de decisão ou acesso ao decisor? 0 / 1 / 2 N — Need Há necessidade real e reconhecida pelo cliente? 0 / 1 / 2 T — Timeline Há prazo definido para a decisão? 0 / 1 / 2

Aba SPIN Selling: Cards com as 4 categorias de perguntas SPIN, com exemplos práticos no contexto Kienbaum:

S — Situação: "Quantos líderes de alta performance vocês têm hoje?" / "Como está estruturado o processo de desenvolvimento de líderes atualmente?"

P — Problema: "Quais são os maiores gaps de liderança que vocês identificam?" / "O que acontece quando uma posição crítica fica vaga?"

I — Implicação: "Como esses gaps impactam os resultados do negócio?" / "O que acontece se não resolverem isso nos próximos 12 meses?"

N — Need-Payoff: "Se tivessem um mapa claro dos sucessores para posições críticas, como isso mudaria a segurança estratégica da empresa?"

Aba Matriz Go/No-Go: Score total (GPCT + BANT, máximo 16 pontos):

12-16 pts → GO — Avançar imediatamente para Desenho da Solução

8-11 pts → CONDICIONAL — Agendar reunião adicional, envolver Sócio se necessário

0-7 pts → NO-GO — Agradecer, manter relacionamento de longo prazo, nutrir

Melhores Práticas (sidebar fixo na página):

✅ Fazer perguntas abertas e aprofundar respostas

✅ Ouvir 70% do tempo, falar 30%

✅ Documentar no CRM imediatamente após

✅ Envolver Sócio em casos complexos

❌ Apresentar solução antes de qualificar

❌ Aceitar respostas vagas sem aprofundar

❌ Avançar sem score mínimo de 50%

1.3 NPS & CSAT

Página com abas: Conceitos | Templates de E-mail | Calculadora NPS | Plano de Ação

Aba Conceitos:

NPS: mede lealdade. Pergunta: "Em uma escala de 0 a 10, quanto você recomendaria a Kienbaum?" Promotores (9-10), Neutros (7-8), Detratores (0-6). NPS = % Promotores - % Detratores. Benchmarks: Excelente 75-100 / Muito Bom 50-74 / Bom 0-49

CSAT: mede satisfação com entrega específica. Escala 1-5. CSAT = (respostas 4-5 / total) × 100. Benchmarks: Excelente ≥90% / Muito Bom 80-89%

Quando usar NPS: fim de projeto (Fase 7), avaliação trimestral/anual de relacionamento

Quando usar CSAT: após entregas específicas, workshops, consultorias pontuais

Aba Templates de E-mail: Dois templates copiáveis (botão "Copiar"):

Template NPS Pós-Projeto: Assunto: [Nome Cliente], sua opinião é muito importante para nós! Corpo: personalizado com campos [Nome], [Nome do Projeto]

Template CSAT Pós-Entrega: Assunto: Como foi sua experiência com [Workshop/Entrega]?

Aba Calculadora NPS: Campos: Promotores (9-10) / Neutros (7-8) / Detratores (0-6) Resultado calculado automaticamente com classificação e cor (verde/amarelo/vermelho)

Aba Plano de Ação:

Detratores (0-6): CP liga/agenda em até 24h, plano de recuperação, envolve Sócio

Neutros (7-8): entender gap, touchpoints adicionais, follow-up em 3 meses

Promotores (9-10): solicitar case/depoimento, pedir indicações, identificar upsell

1.4 Blueprint de Processo

Visualização interativa das 8 fases do processo do Client Partner, navegáveis por setas ou dots de progresso.

Fase 0 — Informações do Cliente (formulário de entrada): Campos: Nome do Cliente, Data do Primeiro Contato, CP Responsável, Sócio da Conta, Setor/Indústria, Valor Estimado (R$)

Fase 1 — Prospecção | Responsável: Freitas + IA + Equipe Kienbaum Objetivo: Identificar oportunidades estratégicas

Backstage: Mapeamento de stakeholders-chave; Acesso à planilha financeira e de projetos; Estudo do cliente (histórico + LinkedIn + clipping) via IA; Rodada de conversa sobre projetos executados e bastidores

Frontline: Freitas apresenta CP ao cliente; CP conduz reunião exploratória; Registro no CRM e Monday

Touchpoints: Contato (ligação/WhatsApp/e-mail), Apresentação do CP, Reunião exploratória

Ação do Cliente: Aceita reunião; manifesta interesse; compartilha informações

Critério de transição: Cliente confirma interesse de continuidade

Fase 2 — Qualificação | Responsável: CP + Responsável vertical + Sócios Objetivo: Qualificar leads com potencial real de conversão

Backstage: Aplicação do framework GPCT/BANT; Atualização do CRM e Monday

Frontline: CP conduz Apresentação Comercial (diagnostica dores, apresenta portfólio, avalia fit, go/no-go)

Touchpoints: Apresentação Comercial de Soluções (slides), CRM e Monday

Critério: Cliente confirma necessidade + orçamento + fit

Fase 3 — Desenho da Solução | Responsável: CP (lead) + Responsável vertical Objetivo: Co-criar proposta customizada e tecnicamente viável

Backstage: CP orquestra estruturação da proposta; Responsável vertical desenha solução customizada; Alinhamento com Sócio Responsável; Registro no CRM

Frontline: CP conduz reunião aprofundada (levantamento de necessidades); CP apresenta proposta preliminar

Critério: Cliente valida escopo + aprovação Sócio/técnica

Fase 4 — Apresentação e Negociação | Responsável: 100% Client Partner Objetivo: Apresentar proposta, negociar e fechar contrato

Backstage: Alinhamento interno final; Validação de alçada com Sócio; Composição do contrato

Frontline: CP apresenta proposta (gestão de objeções, negociação valores/prazos, alinhamento de expectativas); Formalização do contrato

Critério: Contrato assinado + primeira parcela paga

Fase 5 — Handoff | Responsável: CP + Responsável vertical + Sócio | Duração: 1 semana Objetivo: Garantir transição perfeita para equipe de entrega

Backstage: Kick-off Interno OBRIGATÓRIO (transferência de contexto, escopo, riscos, papéis, rituais); Organização da pasta do projeto (Rede)

Critério: Consultor confirma compreensão do contexto + Kick-off cliente agendado

Fase 6 — Execução do Projeto | Responsável: Responsável vertical + Consultores + CP | Duração: 2-6 meses

CP: monitoramento da temperatura do cliente, participação em stand-ups quinzenais/mensais, intervenção em escalações/crises/mudanças de escopo

Critério: Entregas parciais validadas + NPS intermediário >7

Fase 7 — Encerramento | Responsável: CP + Responsável vertical

CP + Consultor apresentam resultados; coleta NPS/CSAT; identificam oportunidades

Critério: Cliente confirma satisfação + feedback documentado

Fase 8 — Pós-Venda e Recorrência | Responsável: 100% Client Partner | Duração: Contínuo

CP agenda touchpoints trimestrais; envio de conteúdos de valor; identificação proativa de necessidades; gestão de upgrades e novos projetos

Critério: Recorrência >70% + NPS >8 + Expansão YoY

Governança e Rituais (tela adicional após Fase 8):

Diário: Atualização CRM pós qualquer interação com cliente

Semanal: Revisão do pipeline e próximas ações

Mensal: Reunião com sócios — revisão da carteira com análise Pareto 80/20 e definição de estratégias por cliente

Trimestral: Touchpoint estratégico com clientes ativos, coleta de NPS

Anual: Planejamento da carteira para o ano seguinte

Cada fase deve exibir: número da fase, nome, duração, responsável, objetivo, camadas (Backstage / Frontline / Touchpoints / Ações do Cliente) e critério de transição. Checkboxes em cada item com campos de data e responsável. Salvar estado via Supabase (não localStorage).

OBSERVAÇÕES FINAIS

Os arquivos do repositório (PPTs, Words listados no Módulo 3.1) serão carregados pela equipe Kienbaum diretamente no Supabase Storage após o app estar estruturado.

Os arquivos HTML (Blueprint, GPCT/BANT, NPS/CSAT, Sistema Intelligence, Sistema Avaliação de Materiais) são os documentos de referência de conteúdo — o app deve incorporar suas informações na interface, não exibi-los como iframes.

O tom de toda a interface deve refletir o padrão Kienbaum: preciso, formal sem ser frio, consultivo, sem excesso de emojis ou linguagem de SaaS popular.

Não usar localStorage para dados de negócio — apenas para preferências de UI (sidebar colapsada, etc.). Todo dado de negócio vai para Supabase.
